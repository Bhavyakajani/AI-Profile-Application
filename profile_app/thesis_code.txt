\section{Introduction}
\subsection{Problem Statement}
Resource allocation in consulting firms requires extensive manual review of candidate profiles, a time-consuming process prone to human error and inconsistency. Traditional methods relying on template matching or rule-based extraction fail to handle the variability in resume formats and lack semantic understanding of contextual information.

\subsection{Project Objectives}
The AI Powered Profile Application aims to:
\begin{itemize}
    \item Automate extraction of structured candidate data (skills, experience, education) from unstructured resumes
    \item Implement semantic understanding of resume content using local LLM (Ollama)
    \item Develop a hybrid storage system combining vector embeddings (Chroma DB) and structured data (MongoDB)
    \item Create a scalable backend pipeline for processing diverse document formats (PDF, PPTX, images)
\end{itemize}

\section{Technology Stack}
\subsection{Core Components}

    \item \textbf{Chroma DB}: Vector database for storing and retrieving document embeddings

    \item \textbf{OpenCV}: Image preprocessing for OCR

\section{Analysis}
\subsection{Approach Comparison}
The system evaluates three primary approaches for resume parsing:

\subsubsection{Rule-Based Extraction (Regex)}
\begin{itemize}
    \item Pros: Simple implementation for fixed patterns
    \item Cons: Fails with varied phrasing and document structures
\end{itemize}

\subsubsection{Named Entity Recognition (NER)}
\begin{itemize}
    \item Pros: Better semantic understanding than regex
    \item Cons: Requires extensive labeled training data
\end{itemize}

\subsubsection{Large Language Model (LLM)}
\begin{itemize}
    \item Pros: Handles format variability and implicit information
    \item Cons: Potential hallucinations and computational cost
\end{itemize}

\subsection{Selected Architecture}
The implemented solution uses LLM as the primary extraction method with the following workflow:
\begin{enumerate}
    \item Document preprocessing (format-specific text extraction)
    \item Text chunking (1500 tokens with 200 overlap)
    \item Vector embedding generation (Ollama embeddings)
    \item Semantic search via Chroma DB
    \item LLM-powered structured extraction with JSON output
    \item MongoDB storage for final profiles
\end{enumerate}

\subsection{Challenges and Solutions}
\begin{itemize}
    \item \textbf{Context Window Limitations}: Addressed through intelligent chunking with overlap
    \item \textbf{Document Format Variability}: Handled by format-specific extraction modules
    \item \textbf{Data Privacy}: Ensured through local LLM execution (Ollama).
\end{itemize}

\section{Conclusion}
The current implementation demonstrates the feasibility of using local LLMs for automated resume parsing while addressing privacy concerns. The hybrid database approach combines the strengths of vector search for semantic understanding with structured storage for exact filtering. Future work will focus on completing the full-stack implementation and optimizing the pipeline for production use.
